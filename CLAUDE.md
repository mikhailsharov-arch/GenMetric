# GenMetric — инструкция агенту

Читается автоматически в начале каждой сессии. Здесь только то, что нужно, чтобы
работать с этим кодом и не повторить уже совершённых ошибок.

Переговоры с заказчиком, доступы, состояние проекта и планы — в папке `Genapp`
на машине Mike (`HANDOFF.md`, `План доработок.md`). Сюда они не попадают: этот
файл лежит в публичном репозитории и переживёт передачу проекта Роману.

## Что это за программа

Настольный индексатор метрических книг: человек перепечатывает в базу написанное
от руки в церковной книге XIX — начала XX века. Tauri 2, интерфейс на React,
данные в SQLite. Windows и macOS. Лицензия GPL-3.0.

**Цель проекта — отдать Роману Чистову работающий инструмент вместе с исходным
кодом.** Отсюда приоритеты: воспроизводимость сборки и понятность кода важнее
всего остального. Стадию сопровождения продакшена мы сознательно не строим —
сопровождать будет сообщество.

Заказчик и единственный настоящий пользователь — **Роман Чистов**, набрал больше
20 000 записей. **Его живой тест перевешивает любые наши рассуждения и замеры.**

Rust проверяется без сборки приложения, из корня репозитория:

    (cd src-tauri && cargo check)

Ожидаемый ответ — «Finished `dev` profile».

**Логика без окна — крейт `src-tauri/core` (`genmetric-core`)**: запросы
(`statement`), нормализация, заполнение xlsx, сборка файлов выгрузки. Его
тесты идут и локально, и в быстрой проверке конвейера (Linux, без Tauri):

    (cd src-tauri && cargo test -p genmetric-core)              # → «test result: ok. 28 passed»

Новая чистая логика — туда же, с тестом; в `src-tauri/src` остаются только
команды окна. С 02.10.2026 в крейте: открытие и обновление базы (`db.rs`),
сохранение записи и разбор ИОФ (`records.rs`), разбор возраста (`age.rs`,
копия `src/age.ts` — правишь одно, правь другое), приходы (`parish.rs`),
импорт из Excel-индексатора (`import.rs`). С 06.10.2026 там же: сборка
запроса подсказок (`suggest_sql`), адрес поиска на Familio
(`familio_search_url`) и перехват паники (`guarded`). Правило «имени в книге
нет» — `records::is_no_name`, его копия для окна — `noNameWord` в
`src/names.ts`: примеры в обоих тестах одни и те же.

**Приходы.** Каждый приход — свой файл SQLite; общий файл
`genmetric-общее.sqlite` (схема — `db/common.sql`) хранит перечень приходов,
настройки окна и общие справочники; сверка — `db/parish_sync.sql` (его же
гоняет `db/test_parish.py`). Дело — на год книги: к делу своего года запись
привязывает `records::save_entry`, не форма.

**Импорт из Excel** проверяется синтетическим индексатором
`db/fixtures/indexer.xlsx` (собирает `python3 scripts/make_indexer_fixture.py`,
данные выдуманы). «Золотая» сверка на файле заказчика — только у
разработчика, файла в репозитории нет:

    GENMETRIC_IMPORT_XLSM=…/Индексатор.xlsm cargo test -p genmetric-core --release import_golden -- --ignored --nocapture

Настоящую программу на чужих данных, не трогая свои, запускает
`GENMETRIC_DATA_DIR=/путь npm run tauri dev`. Выгрузка на настоящей базе и её проверка:

    GENMETRIC_KEEP_DB=/tmp/t.sqlite python3 db/test_export.py
    (cd src-tauri && GENMETRIC_EXPORT_DB=/tmp/t.sqlite GENMETRIC_EXPORT_OUT=/tmp/out cargo test -p genmetric-core export_real -- --ignored)
    dotnet run --project scripts/xlsx-validate -- /tmp/out/familio.xlsx db/export/familio_template.xlsx

**Файл xlsx проверяется валидатором Open XML, а не только тем, что он
«открылся»** (нужен .NET; в конвейере — и в быстрой проверке, и в e2e на
Windows). 01.10.2026 Excel у Романа открыл выгрузку с «восстановлением», хотя
openpyxl и Numbers открывали её чисто.

Шаблоны выгрузки — `db/export/`: образец Familio (прислал Роман, Mike
разрешил держать в репозитории) и шапка листов индексатора, собранная
`db/tools/make_excel_template.py` из его файла. Если `cargo` не найден, значит,
`~/.cargo/bin` не попал в PATH (rustup подключает его через `~/.cargo/env`).
`Cargo.lock` лежит в репозитории: сборка у того, кто получит исходники, должна
взять те же версии крейтов, что и наша.

Python: быстрая проверка в конвейере идёт на 3.14 (он строже), база для
установщика собирается на 3.12. Проверки обязаны проходить на обоих.

**Настоящий Windows есть только в конвейере.** `scripts/e2e/windows.py`
гоняет собранный `genmetric.exe` на раннере `windows-latest`: приложение
запускается с портом отладки WebView2, `msedgedriver` подключается к нему
(подход «attach»; порт открывает само приложение по переменной
`GENMETRIC_E2E_DEBUG_PORT` — `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` на раннере
не сработала; шаг «Сквозная проверка» в `build.yml`).
Всё, что живёт в WebView2 и Rust — транспорт IPC, файловый ввод, ресурсы,
база в папке данных, — проверяется там, а не стендом. Локально этот сценарий
не запустить; его лог читается командой `gh run view <номер> --log-failed`
(номер — из `gh run list`).
Новая команда с байтами или файлом — сначала шаг в этот сценарий.

Рабочая папка `Genapp` лежит вне репозитория, и у того, кто получит репозиторий,
её не будет. Всё, без чего нельзя собрать и проверить программу, лежит в самом
репозитории.

## Проверка работы

Прогоняй **всё** перед тем, как сказать «готово», и показывай вывод.

- Ни одну проверку не пропускать и не удалять. Падает проверка — чини код, а не проверку.
- Тронул Rust — обязателен `cargo check`. Раньше ошибку компиляции ловила только
  сборка на GitHub: через десять минут и уже после пуша.
- Тронул интерфейс — подними стенд и посмотри на форму. Не рассуждай о ней.
- **Тронул выкладку или конвейер — открой страницу выпуска в браузере и посмотри,
  что там лежит.** Тег может указывать на правильный коммит, а установщиков не быть.
- Перед пушем прогоняй проверки на клоне глубиной в один коммит: сборка клонирует
  репозиторий без истории, и на полном клоне проходит то, что там падает. Слепки
  прошлых схем для этого лежат в `db/fixtures/` — из истории git их брать нельзя.

## Правило инцидента

**Инцидент не закрыт, пока на него нет механической проверки.**

Каждая поломка, дошедшая до Романа или до Mike, добавляется в
`scripts/test_incidents.py` отдельной проверкой со ссылкой на дату и суть.
Список в этом файле — не история, а действующая защита: он не даёт вернуть
то, что уже один раз стоило людям времени.

**Проверка приходит вместе с починкой, в том же коммите.** Пока поломка известна,
но не исправлена, она записывается в список `ОТКРЫТЫЕ` в том же файле — он
печатается при каждом прогоне и не даёт о ней забыть.

**Проверка, дающая ложную тревогу, хуже отсутствия проверки:** к ней привыкают
и перестают читать. Прежде чем добавить, сломай код нарочно и убедись, что
проверка падает, а на честном коде — нет.

## Ревью перед выкладкой

Ни один коммит, меняющий доставку до Романа — конвейер сборки, схему базы,
установщик, миграцию, — не уходит в `main` без прохода агента-ревьюера по
`REVIEW.md` и без явного слова Mike. Как это делается — в `REVIEW.md`.

## Что откуда берётся

`intent/` — что просил заказчик, его словами. `spec/` — что мы решили сделать
и почему, с проверяемыми критериями. Пишутся до кода, лежат в репозитории,
меняются коммитами. **Требования не живут в docx**: docx — это письмо Роману,
а источник истины здесь.

## Грабли

Ниже — ошибки, которые уже были совершены в этом проекте. Каждая стоила
человеческого времени.

### Про требования заказчика

**Порядок полей формы — точно как в форме ввода Excel** (лист «МК Ввод», Часть 1).
Условие приёмки, не пожелание. Порядок снимается чтением файла, а не по памяти.

**Наши «улучшения» поверх Excel трижды оказывались вредом.** Разделение счёта на
мужской и женский, автоинкремент счёта «+1 к прошлому», вынос причта в шапку
дела — всё отменено заказчиком. Отступать от Excel можно только с его согласия.
Счёт, который ставится сам **по полу** (08.10.2026, `nextCount` в
`src/count.ts`), — не то же самое: его выбрал сам заказчик, увидев замер на
своих данных (99 % попаданий против 55 % у «+1 к прошлому»), и сам попросил
убрать поле из обхода клавишами. Число, набранное руками, программа до
сохранения записи не трогает.

**Одна и та же жалоба дважды — значит починено не то.** «Список не прячется»
пришёл 24 и 27 августа. В первый раз я нашёл правдоподобную причину, исправил её
и закрыл вопрос; настоящая была рядом. Повторное замечание — повод искать вторую
причину, а не защищать прежнее исправление.

**Проверять допущения о материале на самом материале.** Причт свернули, решив,
что он «меняется раз в дело». На первой же настоящей странице он сменился в 82%
записей. Утверждение о том, как устроен материал, проверяется на сканах или на
данных Романа, а не выводится.

**Просьба к заказчику должна выглядеть просьбой** — отдельным разделом и прямым
вопросом, а не строкой в перечне планов.

### Про права на чужое

**Справочники имён и званий перенесены из Excel-индексатора авторства «А.К.»
(t.me/LinesOfTime). Разрешение на использование в этой программе с открытым
исходным кодом получено от него и от Романа.**

**Сам файл `.xlsm` в репозиторий не выкладывается никогда.** Репозиторий
публичный, а разрешение дано на справочники в составе программы, не на
распространение чужого файла. Исходные `.xlsm` и дамп VBA лежат вне репозитория,
у Mike.

### Про доставку

**Поставка чистая (с 08.10.2026): в установщике нет ни одного населённого
пункта, перечни — по файлу «Справочник» заказчика.** Новый человек не должен
получать чужой приход (Роман: «Мои наработанные данные мешать не должны»).
`db/build_seed.py` без второго аргумента собирает базу без пунктов — так её
собирает конвейер. Проверкам нужен справочник с карточками: они зовут
`build_seed.build(path, places=build_seed.TEST_PLACES)` — это прежний
`seed/place.csv`, теперь `db/fixtures/place.csv`; в установщик и в отпечаток
поставки он не входит. Новая проверка, которой нужны пункты, берёт их так же
или заводит сама.

**Обновление убирает из перечней значения, которых нет в поставке и которые
нигде не стоят** (`migrate.sql`, «Уборка перечней», ответ заказчика 08.10.2026).
«Нигде» — ни в одной записи, ни в одном деле, ни в одном пункте этого прихода.
Записи, упоминания, пункты и память персон уборка не трогает. Значение,
убранное из поставки, но занятое у человека, остаётся у него навсегда. Новый
перечень, который пополняется набором, — добавить в уборку его источник, иначе
занятое значение сочтут свободным.

**База копируется пользователю только при первой установке.** Стоило трёх дней.
Обновление идёт по отпечатку поставки (`db/migrate.sql` плюс `upgrade()` в
`main.rs`); отпечаток считается по `db/seed/*.csv`, `schema.sql` и `migrate.sql`.

**Механизм обновления создаёт недостающие таблицы и простые колонки**
(с 25.09.2026, `add_missing_columns`): новая колонка — только без `NOT NULL`
и `DEFAULT`, иначе у обновлённой базы и у чистой установки схемы разойдутся.

**Всё, что должно доехать до уже установленной программы, проверяется в
`db/test_upgrade.py`.**

**`PRAGMA journal_mode = WAL` в файле схемы валит сборку базы** на смонтированных
и сетевых файловых системах, где WAL не поддерживается. Это настройка соединения,
её включает приложение при открытии базы. SQLite-файлы собирать во временной
папке и копировать на место.

**Windows-раннер запускает Python в кодировке cp1252**, и первый же `print`
кириллицей роняет скрипт. Все скрипты сами переключают потоки на UTF-8
(`_utf8_stdout()`), в конвейере стоит `PYTHONUTF8`. Проверяется локально так:
`PYTHONIOENCODING=cp1252 python3 db/test_entry.py`.

**Сырое тело IPC (`tauri::ipc::Request`, `InvokeBody::Raw`) на Windows не доходит.**
13.09.2026 кнопка загрузки архива у Романа упала с «пришло что-то другое»:
`fetch` на `ipc.localhost` у WebView2 не прошёл, Tauri молча ушёл на
`postMessage`, где тело уже JSON. Байты и файлы — обычными аргументами
(`Vec<u8>`, путь), не сырым телом. Всё, что живёт в WebView2, проверяется
сквозной проверкой на Windows-раннере, а не стендом.

**Windows-установщик только `.exe`.** Msi показывал предупреждение 1946 о свойстве
ярлыка; настройкой это не отключается.

**В выпуске нет `panic = "abort"`** (с 06.10.2026). Разбор чужого файла идёт
под `genmetric_core::guarded`: паника становится ошибкой в окне, а не
закрытой программой и не файлом прихода без строки в перечне. Новый разбор
файла от человека — под тот же перехват.

**С 06.10.2026 Роман ведёт в программе чистовую индексацию.** Обновление не
правит набранного без крайней нужды; всё, что программа подставляет сама
(звание по умолчанию, НП поручителя, фамилия матери), работает только в новой
записи — запись, открытая на правку, автоподстановками не меняется.

### Про молчание

**Никогда не перехватывать ошибку без сообщения человеку.** Ошибки идут через
`report()` из `src/errors.ts`.

**Поле, которое молча ничего не подсказывает, выглядит как «пока не сделано».**
Поле НП искало населённые пункты в перечнях `lookup`, где их нет, и молчало три
недели.

**Шаг конвейера, проверяющий «команда вернула ноль», не проверяет ничего.**
27 августа выпуск ушёл к Роману без установщиков, и сборка отрапортовала успех.
Проверять надо результат, который увидит человек.

### Про код и данные

**Не «чинить» поиск на `COLLATE NOCASE` и `lower()`** — в SQLite они понимают
только латиницу, на кириллице молча возвращают ноль строк. Нормализация обязана
совпадать в `build_seed.py`, `extract_from_xlsm.py` и `normalize()` в `src-tauri/core/src/text.rs`.

**Всё, что трогает данные пользователя, живёт в общем SQL-файле**, который читают
и приложение, и тест: `db/migrate.sql`, `db/statements.sql` (блоки `-- @имя`).
Это касается и чтения: запросы подсказок прятали ошибку, пока лежали в `main.rs`.

**Подстановка `{dict}` в блоке `suggest_ranked` заменяет все вхождения**, включая
те, что внутри комментариев.

**Блок персоны отдаёт форме персону целиком** — вместе с копиями полей,
которые он не менял. Если форма сама подставляет поле (звание младенца, НП
умершего), обработчик `onChange` блока обязан брать неизменённые поля из
текущего состояния, а не из копии блока (`DeathForm.tsx`, 08.10.2026).

**Что подставляется при уходе из поля, должно так же сработать при Ctrl+Enter
из этого поля**: ухода нет, а сохранение идёт. Правило вызывается и в `save()`
(фамилия матери 06.10.2026; звание младенца и счёт по полу 08.10.2026).

**Обход клавишами — `input[data-field], select[data-field]`** (`FIELDS` в
`src/focus.ts`): с 08.10.2026 в нём выпадающие списки свёрнутого причта. У
списка нет `select()` — вызывать через проверку.

**Настройка прихода или общая — решает `COMMON_SETTINGS` в `parish.rs`.** Ключ
из этого перечня `get_setting` читает из общего файла, любой другой — из
файла открытого прихода (выключатели подстановки звания, `src/flags.ts`).

**SQLite в Python и в программе — разных версий, и запрос, прошедший в
Python-тесте, может не собраться в программе.** 08.10.2026: подзапрос с
`ORDER BY`, который ссылался на таблицу внешнего запроса, Python принял, а
rusqlite ответил «no such column». Поймал тест крейта — блоки выгрузки
(`export_prepare`) исполняются и в `cargo test -p genmetric-core`. Новый блок
`statements.sql` должен исполняться настоящим Rust: тестом крейта или шагом e2e.
То же с `migrate.sql`: вложенную цепочку `replace` в сорок уровней SQLite на
Linux не разобрал («parser stack overflow»), хотя на Mac она проходила.
Обновление базы теперь гоняет и тест крейта (`db::tests::upgrade_runs_in_app_sqlite`),
а на настоящей базе — `GENMETRIC_UPGRADE_DB=/путь/копия.sqlite cargo test -p
genmetric-core upgrade_real -- --ignored --nocapture`. Глубокую вложенность в
SQL не писать: считать по шагам во временной таблице.

**Свёрнутый блок формы спрятан, а не убран из окна** (с 09.10.2026,
`src/Fold.tsx`, атрибут `hidden` у блока персоны). Убрать блок — значит
потерять его внутреннюю память: звание, стёртое руками, подставилось бы снова
при разворачивании (ревьюер 09.10.2026). Обход клавишами и окна сверки
скрытые поля пропускают сами (`offsetParent`). Сверка имени у скрытого поля
не идёт, поэтому форма перед сохранением разбирает персон свёрнутых блоков
заново (`stale` в `save()`): жена, подставленная по отцу в свёрнутую мать,
иначе сохранялась без имени. Новая подстановка в блок, который можно
свернуть, — проверить на стенде со свёрнутым блоком. Щелчок по «свернуть» и
по замку не должен забирать фокус у поля (`onMouseDown` с `preventDefault`).

**В память персон и пар идёт написание пункта из справочника**
(`records::place_spelling`), а не набранное: Ctrl+Enter из поля НП сохраняет
текст как есть, и одна персона получала бы в подсказке два написания пункта.

**Замки и свёрнутые блоки — настройки прихода** (`src/flags.ts`: `clergy_lock`,
`confession_lock`, `fold_<блок>`); один выключатель стоит в нескольких местах
сразу, и экземпляры слышат друг друга через событие окна. Закреплённый причт
— `disabled` у списков: обход клавишами пропускает недоступное сам.

**Жена ищется по ИОФ мужа и его НП** (`spouse_lookup`, 09.10.2026). НП мужа в
памяти пар нет — сравнивается НП жены, а он тот же. Спор (НП мужа неизвестен,
жёны из разных пунктов) — никого: чужая жена хуже пустого поля.

**Значение, пришедшее в поле не с клавиатуры, сверяется сразу** — в том числе
слово, выбранное из подсказки, пока человек набирает дальше. Всё, что при
этом правит текст поля, обязано сохранить пробел на конце («ВуколовБаженов»,
09.10.2026).

**Экран «Поиск» только читает** (с 09.10.2026): поиск персоны и досье —
`src-tauri/core/src/search.rs`, слова досье — `src/dossier.ts`
(`scripts/test_dossier.mjs`), экран — `src/SearchScreen.tsx`. Записи в базе
между собой не связаны (`person_id` пуст): персона там — совпадение ИОФ в
современном написании и НП, и досье собирается только из записей, где стоит
её ИОФ. Ребёнок из записи о рождении персоной не считается — у него одно имя.
Слова сопоставляет Rust, а не SQL (кириллица). Копия отбора для стенда — в
шиме: правишь `search.rs` — правь и её. На настоящей базе:
`GENMETRIC_SEARCH_DB=/путь GENMETRIC_SEARCH_QUERY="иван кап" cargo test -p
genmetric-core --release search_real -- --ignored --nocapture`.
Имена в строках досье стоят в именительном падеже после тире: склонять
книжные написания программа не умеет.

**Память поиска — по счётчику изменений соединения** (с 10.10.2026).
Упоминания прихода для экрана «Поиск» лежат в памяти программы
(`search::Index`, в `main.rs` — `App.search`); свежесть проверяется числом
`SELECT total_changes()` у соединения прихода, а при смене прихода память
сбрасывает `drop_search` (у нового соединения счёт свой и может совпасть).
Новое место, где соединение прихода заменяется, — обязано звать `drop_search`.

**Команда окна с базой идёт под перехватом паники** (с 10.10.2026):
`with_conn` → `genmetric_core::guarded_db` — паника становится ошибкой в
окне, незаконченная транзакция откатывается. Замок соединения брать только
через `lock_conn` (отравленный берётся всё равно), не `app.conn.lock()`.

**Месяц по дню — одно место для рождений и смертей**: `settleMonths` в
`src/month.ts`. Формы читают дни и месяцы из `monthsNow` (ссылка), а не из
замыкания: Ctrl+Enter в поле дня сначала уводит фокус (месяц решён), и
сохранение в том же событии иначе записало бы прежний месяц.

**Сканы рядом с формой** (с 10.10.2026, схема базы 11): всё в `src/scan.tsx`
— состояние (`ScanProvider`), блок (`ScanPane`), связь с записью
(`useEntryScan`); порядок файлов — `src-tauri/core/src/scans.rs`; команды —
`scan_state`, `scan_set_dir`, `scan_remember`, `scan_window` в `main.rs`.
Просмотрщик — OpenSeadragon (BSD-3; лицензия в ресурсах установщика, как у
шрифта). Что нельзя сломать:
- **Мышь в скане не уводит курсор из поля формы.** Уход из поля ИОФ — это
  сверка недописанного имени и окно поверх набора. Поэтому у просмотрщика
  отключён собственный захват фокуса (`v.canvas.focus`), нажатие мыши в блоке
  отменяется на перехвате, кнопки блока — с `onMouseDown preventDefault`.
- **Окно видит только выбранную папку**: в `tauri.conf.json` список путей
  протокола `asset` пуст, папку разрешает Rust
  (`asset_protocol_scope().allow_directory`) при выборе и при открытии.
- **Папка сканов — настройка прихода по году дела** (`scan_dir_<год>`,
  `scan_last_<год>`), путь у каждого компьютера свой; у записи — только имя
  файла (`entry.scan_file`). Вид окна (`ui_scan_on`, `ui_scan_form_width`) —
  общая настройка.
- **Запись на правке свой файл не меняет и чужой не получает**, пока человек
  не нажал «привязать»; показ разворота (правка, ссылка «скан») не затирает
  место набора (`peek`/`show`/`back`). Папка — у дела: файл записи другого
  года книги из открытой папки не показывается и новой записи не пишется.
- **Окно выбора папки открывает Rust** (`scan_pick_dir`): команда плагина
  `dialog` разрешила бы окну папку со всеми вложенными. Разрешений
  `dialog:*` у страницы нет.
- **Новый пакет npm — проверить `git status package.json`**: до 10.10.2026
  скрипт стенда возвращал `package.json` из git и стирал запись о новой
  зависимости (локально собиралось из `node_modules`, конвейер упал бы).
- **Правила раскладки по ширине — `@container app`, не `@media`**: рядом со
  сканом окно широкое, а колонка формы узкая. Контейнер — `.shell` без скана
  и `.appcol` со сканом. `@media` в стилях больше нет.
- Системное окно выбора папки роботу недоступно: стенд и e2e подставляют путь
  через `window.__pickScanDir`. Стенд показывает картинки из `scans/` своего
  сервера (шим, `convertFileSrc`); настоящий протокол проверяет только e2e.

**Клавишу слушать по коду, а не по букве** (`e.code === "KeyF"`): в русской
раскладке Ctrl+F приходит как «а». Esc на экране с подсказками — на
перехвате: иначе поле успевает закрыть список, и тот же Esc уводит с экрана.

**Асинхронный ответ надо уметь отменять.** Где запрос уходит на каждое нажатие,
закрытие списка обязано увеличивать счётчик запросов.

**Две правки одного блока персоны подряд затирают друг друга**, если обе
берут за основу состояние из прошлой перерисовки: ответ разбора имени приходит
асинхронно и нёс с собой старое звание (стенд 06.10.2026). Правки блока идут
через `push()` в `PersonBlock.tsx` — от последнего известного состояния.
Подстановку «вслед за другим полем» определять признаком «набрано руками», а
не сравнением с прошлым подставленным значением: при быстром наборе оно
отстаёт на букву.

**В словаре имён у заголовочного написания приоритет над вариантом.** Иначе
«Никита» превращается в «Аникиту».

**Книги написаны дореформенной орфографией**, словари — современной: «Иванъ»
против «Иван». Всякая сверка со справочником сравнивает, отбрасывая конечный «ъ».

**Поиск по началу строки не ловит ошибку чтения.** «Букарина» вместо «Бухарино» —
расхождение на третьей букве, подсказка молчит, автопополнение заводит дубликат
навсегда.

**Пункт во всей программе узнаётся по названию** — форма хранит название,
сверка приходов, слияние двойников и память персон сравнивают названия.
Поэтому комментарий деревни-тёзки (08.10.2026) — часть названия внутри
программы: «Хмельничное (Столпино)» в `place.name`, в поле НП и в памяти
персон; сам комментарий — в `place.comment`. **Наружу — в выгрузки Familio и
Excel — идёт чистое название**: `text::place_clean`, выражение со `substr` в
`export_prepare` и `familio_location`, `:clean` в `place_save` и
`place_update`. Новый вывод названия пункта за пределы программы — через
чистое название. Метку собирает `text::place_label` (копия в окне —
`placeLabel` в `src/names.ts`).

**Название населённого пункта — колонка 10 листа «НП»** («НП для ввода МК»),
а не колонка 1.

**Шрифт Inter вшит в программу** (`src/fonts/`, лицензия OFL рядом): интерфейс
и стенд выглядят одинаково на любой системе. Верхняя строка окна при ширине
по умолчанию занята целиком — новой кнопке в ней места нет. Переключатель «в
столбик» поэтому стоит на экране «Дело» (с 08.10.2026) и **изначально
включён**: выключенным считается только явное «0» в настройке.

**В стилях нет абсолютных размеров, кроме рамок и скруглений.** Всё масштабируется
переменной `--ui-scale`, за этим следит `scripts/check_styles.py`. **Высота — самый
дефицитный ресурс формы:** заказчику нужно видеть запись целиком, пока справа
открыт скан.

**Не ломать соответствие шаблону Familio** — выгрузка должна совпадать на 100%.

### Про самопроверку

**«Открылось» не значит «цело».** Выгрузка #39 открывалась в openpyxl и
Numbers, а Excel у Романа предложил её восстановить: из `[Content_Types].xml`
пропали `<Default>`. Файл чужого формата проверяется валидатором формата
(`scripts/xlsx-validate`) и, по возможности, той программой, которой его
откроет человек.

**Проверять, что «невозможно», а что просто не пробовали.** Три недели в проекте
стояло «браузер не запускается»; на опровержение ушёл час. Ограничение, записанное
со слов, а не по свежей проверке, проверяется заново.

**Правило, исполненное буквально, может промахнуться мимо смысла.** «Проверь, на
какой коммит указывает тег» было исполнено дословно — а страницу, которую откроет
человек, никто не открыл.
