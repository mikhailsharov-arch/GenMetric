# Разовые утилиты и замеры

Здесь лежат инструменты, которые запускаются вручную и в сборку приложения не входят.

`extract_from_xlsm.py` — перенос справочников из Excel-Индексатора в `db/seed/*.csv`.

`parse_lab.py`, `rank_lab.py`, `iof_lab.py` — замеры на настоящих данных. Им нужен файл `persons.json`, выгруженный из рабочего файла индексатора; сам этот файл в репозиторий не кладётся, потому что содержит чужую работу целиком.

## Что показали замеры

Проверялось на 3664 персонах и 1834 записях прихода Борисоглебское — полгода настоящей работы.

**Разбор строки ИОФ на части** (`parse_lab.py`): разбиение верно в 99,7% случаев, предложенное осовременивание совпадает с выбором индексатора в 99,9%. Именно это позволило объединить три поля ввода в одно.

**Экономия нажатий** (`rank_lab.py`), подсказка по частоте против алфавитного порядка:

| поле | целиком | по частоте | по алфавиту |
|---|---|---|---|
| звание | 48 695 символов | 10 217 нажатий, экономия 79% | 18 679, экономия 62% |
| населённый пункт | 32 631 | 5 399, экономия 84% | 7 372, экономия 77% |

С первой же буквы верное звание попадает в тройку подсказок в 82,5% случаев при сортировке по частоте и лишь в 32,1% при сортировке по алфавиту. Это и есть цена претензии из опросника.

**Пословная подсказка ИОФ против поиска строкой целиком** (`iof_lab.py`): 64% экономии против 18%. Сочетание имени с отчеством почти всегда уникально, поэтому искать персону целиком бесполезно — а сами имена и отчества повторяются постоянно.
