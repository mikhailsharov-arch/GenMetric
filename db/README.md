# Слой хранения

Схема базы данных, справочники и их сборка.

## Файлы

`schema.sql` — схема SQLite, версия 1: справочники, дела, записи, персоны, связи персон, частоты для автоподстановки, настройки.

`seed/` — справочники в текстовом виде. Именно они, а не собранная база, лежат в git: изменения видно построчно в истории.

| файл | что внутри | строк |
|---|---|---|
| `name_dict.csv` | русские имена, варианты написания, отчества старой и современной формы | 3112 |
| `lookup.csv` | плоские перечни: архивы, церкви, губернии, уезды, звания, вероисповедания, причины смерти, типы населённых пунктов, окончания фамилий | 423 |
| `lookup_kind.csv` | названия перечней для интерфейса | 14 |
| `role.csv` | роли персон в записи и возрастные коридоры для прогноза года рождения | 21 |
| `place.csv` | населённые пункты | 0 |
| `setting.csv` | настройки по умолчанию | 12 |

`build_seed.py` — собирает `seed.sqlite` из этих CSV.

`verify_seed.py` — 36 проверок: целостность базы, сверка количеств с CSV, поиск по префиксу на кириллице, ранжирование подсказок, содержимое словаря имён.

`tools/extract_from_xlsm.py` — разовый перенос справочников из Excel-Индексатора в CSV. Запускается вручную и только при обновлении справочников.

## Сборка

```bash
python3 build_seed.py            # соберёт seed.sqlite
python3 verify_seed.py           # проверит
```

Собранная база в git не хранится: она полностью выводится из CSV.

Обновить справочники из новой версии Excel-Индексатора (файл нужен локально, в репозиторий он не выкладывается):

```bash
python3 tools/extract_from_xlsm.py "путь/к/Индексатор МК 20260806.xlsm"
git diff db/seed/                # посмотреть, что изменилось
python3 build_seed.py && python3 verify_seed.py
```

## Четыре решения, которые стоит знать перед правкой

**Форма ввода и хранение разделены.** В Excel порядок полей и структура данных были одним и тем же: перенос делался копированием диапазона по номерам колонок, поэтому там любое перемещение поля ломало выгрузку. Здесь порядок полей на экране можно менять как угодно, схема при этом не трогается.

**Поиск по префиксу идёт по колонкам `*_norm`, а не через `COLLATE NOCASE`.** Встроенный NOCASE в SQLite приводит регистр только для латиницы: запрос `value LIKE 'КР%' COLLATE NOCASE` на кириллице возвращает ноль строк. Проверка №4 в `verify_seed.py` фиксирует это специально, чтобы схему не «упростили» обратно. Нормализацию (нижний регистр, ё → е, схлопывание пробелов) делает функция `norm()`, и она обязана совпадать во всех трёх местах: `build_seed.py`, `extract_from_xlsm.py` и код интерфейса.

**`journal_mode = WAL` не задаётся в схеме.** Это настройка соединения, её включает приложение при открытии базы. В `schema.sql` она ломает сборку на сетевых и виртуальных файловых системах.

**Приход опознаётся отдельным ключом** `mk_case.parish_key` (церковь, село, уезд, губерния). Благодаря этому накопленная статистика подсказок переходит между годами одного прихода — а индексируют именно приходами, год за годом.

## Ранжирование подсказок

Порядок выдачи: текущее дело → приход → вся база → словарь; внутри группы по убыванию частоты. Готовый запрос с этой логикой лежит в `verify_seed.py`, проверка №5 — оттуда его и надо брать в код приложения.

## Происхождение справочников

Справочник имён и перечни перенесены из Excel-Индексатора метрических книг авторства А.К. (t.me/LinesOfTime) с его разрешения. Сам файл Индексатора в репозиторий не выкладывается и закрыт в `.gitignore`.
