# Спецификация: сборка #40 (срочная) — выгрузка открывается в Excel, места, комментарий, оформление

По замыслу `intent/2026-10-01-otchyot-romana-01-10.md`. Состав утвердил Mike

технический релиз (подсказка с отцом, фокус после «+/−», память причта,
техдолг) — следующим.

## Ошибка: Excel открывал выгрузку в Familio с «восстановлением»

1. **Причина.** `drop_children()` в `xlsx.rs`, убирая из `[Content_Types].xml`
запись о `calcChain`, собирала содержимое заново из одних `<Override>` и
теряла все `<Default>` (типы частей `.rels`, `.xml`, `.bin`, `.vml`). Найдено
валидатором Open XML: «A required part … officeDocument is missing».
openpyxl, Numbers и разбор XML в e2e такой файл открывали.
**Исправление.** Функция вырезает только элементы, подошедшие под условие,
остальное содержимое обёртки не трогает.
**Защита.** Тест `xlsx.rs` сверяет число `<Default>` и `<Override>` с
образцом; `scripts/xlsx-validate` (Open XML SDK) в репозитории; e2e на Windows
гоняет через него оба файла выгрузки (ошибки самого образца Familio — 12
про `pageSetup` — в счёт не идут); инцидент `20261001_excel_vosstanovlenie`.
Критерий: валидатор — 0 новых ошибок на тестовой базе, пустой базе, базе из
одних браков и на 17,5 тыс. записей. Окончательно подтверждает Роман в Excel.

## Места: пустые location, full_location, person_location

2. **Причина.** Пункты у Романа пришли архивом 13.09 одним названием;
`migrate.sql` добавляет пункт поставки, только если названия ещё нет, —
подробности поставки (тип, волость, уезд, губерния, ссылка Familio) до его
базы не доезжали.
**Исправление.** `migrate.sql`: пункт без единой подробности получает их из
поставки по `name_norm`; заполненный или поправленный человеком — не
трогается. Критерий: `test_upgrade.py` — пункт из архива получил тип, уезд,
полное место и ссылку; поправленный «Бухарино» остался как был.
**Причина не подтверждена на базе Романа** (ревьюер #40): по истории кода
архив мог добавить лишь ~9 пунктов; вероятнее «двойники» — пустая строка
пункта рядом с полной строкой поставки, и записи ссылаются на пустую. Поэтому
выгрузка не полагается на одно обновление: подробности берутся у самой
полной строки с тем же названием (`x_place`), на листе location пункт один
раз; `place_find` для новых записей выбирает полную строку. Критерий:
`test_export.py` §10 (двойник, пункт без подробностей). Попросить у Романа
копию базы — подтвердить.
Выгрузка: person_location и full_location — полное место, а у пункта без
подробностей — краткое или название (не пусто); село дела берёт самую полную
строку пункта; села без карточки — строкой с названием на листе location.

## Оформление выгрузки в Excel

4. Роман 01.10: «ширина колонок, высота строк, перенос текста по словам,
цвета заливки ячеек должно быть полностью идентично». Шаблон
`db/export/excel_template.xlsx` теперь несёт стили и тему индексатора
целиком, шапку с её стилями и высотами, ширины и группировку колонок,
закрепление, цвет ярлыка и строку-образец данных (высота 63,75, стиль ячейки
каждой колонки). `xlsx.rs` берёт из образца высоту строки и стиль ячеек;
стиль колонки равен стилю ячейки образца — пустые ячейки с рамками без
записи в файл. Новые колонки (восприемники 3–4, поручители 5–6) оформлены
как восприемник/поручитель 1. Критерий: снимок листа «МК» рядом с
индексатором; валидатор — 0 ошибок.
