## 1. Ошибки и недоработки

1. **п. 73 — НП безымянному родственнику жениха и невесты.** Родственник
   одним родством («отец» — у всех записей Романа) получает НП жениха
   (невесты), как названный: при сохранении (`records::save_entry_in_tx`) и
   для набранного раньше (`migrate.sql`). Совсем пустой — нет. Память персон
   не меняется: безымянного в ней нет, а строка без НП и так прячется при
   строке с НП.
2. **п. 76 — заморозка листания видна.** Пока страница не идёт за сканом
   (перешли на вкладку, набор не начат) и при этом шла бы (новая запись,
   открыта папка года формы), у подписи «Стр.» — значок ⏸ с объяснением в
   подсказке, поле подсвечено. Начали набор — значок уходит. Высоту формы
   не меняет. Значок виден стилем по атрибутам формы (`data-scan-frozen`,
   `data-scan-follow`), без состояния React — см. «Что нашли агенты».
3. **п. 69 — невеста без фамилии и тёзка-девочка.** Рождение в деревне
   невесты с тем же ИО прикрепляется к невесте без фамилии только
   «возможно» (как к матери — с 15.10): фамилию сверить нечем.
4. **п. 78 — исповедовавший в выгрузке Familio.** Исповедовавший (пометка
   «исповедовал») при другом священнике той же категории — только в
   колонке «исповедовал» листа СМЕРТЬ; погребал другой; в свободную
   колонку дьякона он не идёт. Так же раскладывает импорт Familio. У Романа
   смертей с двумя священниками и пометкой нет (проверено по его базам
   20.10) — его выгрузки не меняются.
5. **п. 79 — «ФИО» одной колонкой при импорте Familio.** Три слова, имени
   из словаря нет, последнее похоже на отчество («Иванова Мароа
   Михайлова») — порядок шаблона: фамилия, имя, отчество.
6. **п. 80 — пункт без карточки после импорта Familio** (нет ни типа, ни
   уезда, ни губернии) — на сверке, одной строкой на пункт, с первой
   записью; число — в итоге.
7. **п. 81 — повторный импорт Familio заменяет приход**, как у Excel: если
   все уже импортированные файлы — из одного прихода, окно предлагает
   «создать ещё один» или «заменить приход» (прежний файл остаётся с
   пометкой «заменён»). Из разных приходов — только предупреждение.

## 2. Техдолг

1. **Словарь отчеств для списка смертей — один раз** на список
   (`search::patronymics`, `child_full_iof_in`), а не на каждого младенца.
   Ответ тот же (тест крейта).
2. **`x_place` без квадрата.** «Лучшая строка» пункта ищется двумя
   поисками по индексам (название, чистое название) вместо одного «ИЛИ», при
   котором индекс не работал: 3 тыс. пунктов — 0,02 с вместо 1,04 с, 24
   тыс. — 0,11 с. Выбор тот же: сверено на четырёх приходах Романа.
3. **п. 68 — память поиска не держится с начала набора.** Подсказке нужны
   только годы смерти («†»): фоновая сборка оставляет их (`Index::deaths`),
   а саму память выбрасывает. Память экрана «Поиск» отпускается, когда с него
   уходят (`search_release`); вернулись — читается заново.

## Что нашли агенты (21.10.2026)

**Проверяющий (sonnet): «нельзя»** — блокер, исправлен: значок ⏸ был
состоянием React, и снятие заморозки на событии `input` перерисовывало форму

п. 73 в выгрузках не виден — безымянный родственник не выгружается ни в
Familio, ни в Excel (условие `iof_b <> ''`); НП теперь лежит только в базе
(досье, будущая правка записи). Роману об этом — прямо, НП в выгрузке не
обещать.

**Ревьюер (opus): «пропускает»**, исправлено: при двух исповедовавших строка
смерти в выгрузке Familio задваивалась (колонка 0 — одному; тест в

приход» при повторном импорте Familio — только тем же набором файлов, иначе
предупреждение с недостающими файлами; пункты без карточки на сверке — по
названию, без повторов. Оставлено: если уйти с экрана «Поиск», пока его память
ещё читается, она доживает до следующего ухода (низкая).
