# Копия прихода для помощника (задача 2 бэклога)

19.11.2026. Выбор Романа: задача 2 «Кнопка „Выгрузить базу для помощника“».
Идёт в ту же ветку `test/cvet-strok` и ту же выкладку, что цвет строк.

Постановка (Бэклог, р. 1, задача 2): «Сохранить копию файла прихода в
понятное место (Рабочий стол, Документы, Загрузки) — чтобы не искать файл в
скрытой папке AppData». Как проверить: «Кнопка сохраняет копию на Рабочий
стол с понятным именем (приход и дата); … рабочий файл не тронут».

## Что делаем

**Окно.** В окне «Приходы» у каждой строки — кнопка «Копия…» рядом с
«Переименовать» и «Удалить» (`src/ParishDialog.tsx`). Нажатие открывает
системное окно «Сохранить как»: папка — Рабочий стол, имя —
`<название прихода> — копия ДД.ММ.ГГГГ.sqlite`. После сохранения — строка
«Копия сохранена: <путь>» и кнопка «Показать в папке» (готовая
`reveal_path`). Отмена окна — ничего не происходит. Пропавший файл прихода
(`missing`) — кнопка недоступна, как «Открыть».

**Rust.**
- `genmetric_core::parish::export_copy(dir, id, target) -> Result<PathBuf, String>`:
  - файл прихода — `parish::file_path` (как у открытия);
  - копия — `VACUUM INTO` с отдельного соединения только для чтения к файлу
    прихода: согласованный снимок вместе с тем, что ещё лежит в `-wal`
    открытого прихода (простое копирование файла `-wal` теряло бы — п. 131),
    без свободных страниц;
  - **отказ, если `target` внутри папки данных** (`dir`): копия поверх
    рабочего файла или в «приходы» недопустима;
  - `target` существует (человек согласился заменить в окне) — удаляется
    перед `VACUUM INTO` (он требует пустой путь);
  - имя по умолчанию — `export_name(name, date)`: символы, запрещённые в
    именах файлов Windows (`\ / : * ? " < > |`), заменяются на «_».
- Команда окна `parish_export(id, path: Option<String>)` — `command(async)`
  (копия большого прихода не должна держать главный поток): `path` пуст —
  Rust открывает окно «Сохранить как» (`tauri_plugin_dialog`,
  `blocking_save_file`, папка — `desktop_dir`), отмена → `None`. Путь
  передан — без окна (так подставляют путь стенд и e2e, как
  `window.__pickScanDir`; хук окна — `window.__pickExportPath`).
- Метка прихода (`setting.parish_uid`) в копии та же, что в приходе: так и
  нужно — слияние копии узнаёт её по метке (`merge_origin`).

**Чего не делаем.** Облачную папку обмена (задача 1) и открытие копии как
нового прихода на другом компьютере — не делаем: помощник присылает свой
файл, а Роман его сливает («Слить с файлом помощника…»), это уже есть.

## Критерии

| Критерий | Проверка |
|---|---|
| Копия — тот же приход: записи, метка прихода, целостность; данные из `-wal` открытого прихода в копии есть | тест крейта `parish::tests::export_copy_*` |
| Копия в папку данных — отказ; существующий файл заменяется; рабочий файл прихода не меняется (размер и время) | тот же тест |
| Копию принимает «Слить с файлом помощника» (`merge::inspect`) | тот же тест |
| Имя по умолчанию: приход и дата, без запрещённых символов | тест крейта `export_name` |
| В окне: кнопка «Копия…» у строки, после сохранения — путь и «Показать в папке»; у пропавшего прихода кнопка недоступна | стенд, `_стенд/s83.mjs` (команда — в шиме, путь — через хук) |
| Настоящий файл на Windows | шаг в `scripts/e2e/windows.py`: `parish_export` с путём во временной папке → файл есть, открывается, записей столько же |
| Регресс | все проверки `CLAUDE.md`, `cargo check`, `npm run build`, `s81`, `s82` |
