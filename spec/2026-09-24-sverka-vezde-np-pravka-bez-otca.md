# Спецификация: сверка после автоподстановки, правка НП, высота окна, записи без отца

По замыслу `intent/2026-09-24-otchyot-romana-24-09.md`. Состав — Mike 24.09:
пп. 1–5 разбора плюс приоритет № 3 Романа. Правило Mike с 24.09: каждый
релиз выходит с новой функцией, если нет критичных поломок.

## 1. Сверка и после заполнения не с клавиатуры

Сегодня `IofField.checkOnLeave` запускается только на blur. Мать
заполняется от мужа (`suggest_spouse`), восприемник — выбором персоны
(`pickPerson`), запись на правку — `openEntry`; фокус после этого уходит
к следующему **пустому** полю, заполненное не покидается — сверки нет.

Решение: разбор (`parse_iof`) идёт на каждое изменение; если изменение
пришло не с клавиатуры (`typed` ложь) и разбор дал алиас или неизвестное
имя/отчество — та же логика, что при уходе из поля (`decide()`): замена по
алиасу с примечанием, иначе окно. Одно окно на приложение — остальные
несверенные ловит защита при сохранении и называет персону.

Критерии: стенд `auto.mjs` — отец выбран из персон (`person_index`) с
неизвестным именем → окно без выхода из поля; жена подставлена от мужа с
неизвестным отчеством → окно; открытие записи с несверенным именем → окно.
e2e шаг 8 без изменений.

## 4. Правка карточки известного НП

У поля НП (не у причта) справа ссылка «карточка», видна когда поле
непустое. Клик: `place_get(name)` → карточка в режиме правки: заголовок
«Населённый пункт: «X»», поля заполнены из базы, без списка похожих,
кнопка «Сохранить изменения» → `place_update` по `name_norm`
(short/full_location пересобираются). Если пункта нет — обычный путь
`place_check` (похожие/новая карточка). Так же дозаполняются места из
архива Excel (без губернии и уезда).

Критерии: `test_parse.py` — `place_get`, `place_update` меняет губернию и
пересобирает `full_location`, `name` не меняется; стенд `place.mjs` —
ссылка открывает карточку с полями из базы, правка сохраняется, повторное
открытие показывает новое.

## 5. Высота окна по экрану

`main.rs`, после `builder.build()`: рабочая область текущего монитора
(`current_monitor().work_area()`, без панели задач); высота внутренней
части = высота области минус рамка окна (outer − inner); окно ставится
к верху области. Ширина не меняется. Ошибка тут не роняет запуск — `let _`.
Проверяется только настоящей сборкой (снимок e2e покажет).

## 6. Записи без отца (приоритет № 3 Романа)

Сегодня `NEW_MOTHER` сразу несёт «законная жена его», а НП матери
копируется от отца — в незаконнорождённых приходится стирать. Решение:
новая запись — мать без звания; звание «законная жена его» подставляется
в момент, когда у отца появляется ИОФ (и у матери звание пусто); если ИОФ
отца стёрт до пустого — подставленное звание и скопированный НП у матери
убираются (свои, набранные руками, — нет). Заполненный вручную мать до
отца — не трогается.

Критерии: стенд `nofather.mjs` — пустой отец: у матери звание и НП пусты,
сохранение проходит; набрали отца — «законная жена его» и НП появились;
стёрли отца — исчезли; своё звание матери при стирании отца остаётся.
`test_entry.py` без изменений (звание матери — поле формы).

## 8. Техдолг этого релиза (правило Mike с 24.09: ~35% долга за релиз)

Из восьми пунктов долга — три дешёвых с заметной пользой:

- **«ѳ» → «ф»** в `normalize_name` (Rust, шим, тест): «Ѳома» — «Фома» без
  окна. Критерий: `test_parse.py`.
- **Устаревшая пометка сверки.** Сменили человека в поле («Кесарь …» →
  «Иван …») — «Имя в документе: Пискарь» уходит; трогается только та самая
  пометка, что дописана в этом блоке, и пока она есть в примечании.
  Критерий: `names.mjs` шаг 6; инцидент `20260924_pravka_sterla_pometku`.
- **«Это не отчество» запоминается** — соответствие отчества без цели,
  `parse_iof` больше не спрашивает. Автосверка сделала окно назойливым
  (проверяющий 24.09). Критерий: `test_parse.py`.

Сначала выбрано было переименование «д.Балахонка, Заобнорская волость» в
поставке — отменено: это нарочная конвенция Excel для чужого прихода
(колонка 10 листа «НП», грабли CLAUDE.md), ревьюер 24.09.

Попутно по находкам агентов: пункт поставки, поправленный в карточке, при
обновлении не заводится заново (`migrate.sql`, NOT EXISTS по `name_norm`,
`test_upgrade.py`); НП матери убирается при стирании отца, только если
скопирован, и копируется снова при перенаборе.

Остаётся: «ъ» в званиях; быстрый набор после Enter уходит в поиск окна;
стенд не пишет частоты; `Cargo.lock` и NFC в `normalize`; название НП в
карточке не правится (Роман просил «отредактировать НП» — спросить).
