По замыслу `intent/2026-09-23-otchyot-romana-23-09.md`. Состав выбрал Mike

## 1. Сверка имён и отчеств со справочником

Сегодня: неизвестное имя получает подпись «имени нет в словаре», запись
сохраняется. Роман (28.08, 23.09): «нельзя пропускать несуществующие имена»,
и его проект окна — принят целиком.

**Когда.** При уходе из поля ИОФ (Tab, Enter, клик мимо) после разбора,
если первое слово не найдено в `name_form` (kind name/variant) и не найдено
в пользовательских соответствиях. Для отчества — если слов три и больше,
второе не опознано как отчество и похоже на него по окончанию
(-ов/-ев/-ин/-ова/-ева/-ина/-ич/-на, с «ъ» и без). Ребёнок, отец, мать,
восприемники — все; причт тоже.

**Сначала без окна — «ъ».** Перед поиском конечный «ъ» отбрасывается
(`Иванъ` → `Иван`, `Петровъ` → `Петров`) в `normalize_name()` в `main.rs`;
в поле остаётся как набрано, современное — из словаря. Так закрывается
просьба от 28.08 без единого окна.

**Окно.** Модальное, с клавиатуры целиком: заголовок «Какому имени из
справочника соответствует „Пискарь“?», поле поиска с фокусом, под ним
список — сначала похожие (`similar_names`: расстояние Дамерау — Левенштейна
по нормализованным формам, бонус за общее начало, пол персоны сужает
список, если известен), дальше по вводу в поле поиска — обычный префикс.
Enter — выбрать, «Запомнить» — то же. Кнопки: **«Запомнить»** (основная),
**«Новое имя»** (имени в справочнике действительно нет — спросить пол,
если не ясен, и занести как самостоятельное), **Esc** — назад в поле,
исправить набор.

**После «Запомнить».** В поле ИОФ имя заменяется на выбранное (Кесарь);
в примечание персоны дописывается «Имя в документе: Пискарь» (для отчества
— «Отчество в документе: …»), примечание разворачивается. Соответствие
сохраняется в новой таблице `name_alias` (kind name/patr, form, form_norm,
target — имя или отчество из словаря текстом, gender, created_at) —
**своей, не в `name_form`**: обновление стирает и перезаливает
`name_dict`/`name_form` из поставки (`migrate.sql`), пользовательские
строки там не выживут; связь по тексту, а не по id, потому что id словаря
между поставками не обещаны. `parse_iof` смотрит `name_alias` раньше
словаря и отдаёт `name_alias`/`patr_alias`; форма при уходе из поля делает
то же, что при первом решении — подставляет целевое имя и дописывает
«Имя в документе: Пискарь», — только без окна. Так запись выглядит
одинаково, решалась она вручную или по памяти.

**После «Новое имя».** Строка в `name_alias` с `target = NULL`, пол
выбранный (если роль пола не задаёт и отчество не подсказало — окно
спрашивает); далее имя считается известным, современное = само.

**Критерии.** `db/test_parse.py` (новый; повторяет запросы `parse_iof_in`
и правило `normalize_name`, сверяя текст `main.rs`): `Иванъ` → known,
modern `Иван`; `Пискарь` → unknown; после alias → known, modern `Кесарь`;
отчество `Петровъ` опознано; соответствие переживает обновление
(`test_upgrade.py`). Стенд `names.mjs`: набрать «Пискарь Иванов Сидоров» →
окно, выбрать «Кесарь», поле = «Кесарь Иванов Сидоров», примечание содержит
«Имя в документе: Пискарь»; повторный набор «Пискарь» — окна нет, замена и
примечание есть; Esc — окно закрыто, повторный уход не открывает; Ctrl+Enter
с несверенным именем — не сохраняется; «Новое имя» с полом. Похожие: для
«Пискарь» — «Кесарь». e2e шаг 8: окно на Windows открывается на Tab и
закрывается Enter.

**Порог похожести.** Имена — треть длины, не меньше 3 (Пискарь → Кесарь = 3);
места — четверть, не меньше 2: в карточке Enter выбирает первое похожее,
и ложное похожее («Неверовка» к «Новодеревенька») там опасно.

## 2. Карточка населённого пункта при первом вводе

**Когда.** При уходе из поля НП (у любой персоны), если `place_find` по
нормализованному названию пуст. Не при сохранении — иначе Ctrl+Enter
упрётся в окно посреди потока.

**Окно.** Сверху — **похожие из справочника** («Букарина» → «Бухарино»,
тот же алгоритм похожести по `place.name_norm`): выбор Enter подставляет в
поле, карточки не будет. Ниже — карточка нового НП: название (как набрано,
без типа), тип (перечень `np_type`, по умолчанию «д.»), губерния и уезд
(перечни с «▾», **по умолчанию из шапки дела**), волость, ссылка на
Familio (необязательно). «Сохранить» — `place_insert` с полями,
`short_location` = «тип название», `full_location` = «тип название,
волость, уезд уезд, губерния губерния». Esc — назад в поле.

**Не в этом объёме.** Дозаполнение мест из архива Excel (без губернии и
уезда) — они и сегодня «известны», окно для них не откроется. Отдельным
пунктом позже: «Открыть карточку» у известного НП.

**Критерии.** `db/test_parse.py`: `place_save` собирает short/full_location,
`place_find` после вставки, «Бухарино» — первое похожее на «Букарина», на
«Новодеревенька» ложных похожих нет. Стенд `place.mjs`: «Букарина» → окно,
фокус на списке похожих, Enter → «Бухарино», фокус в звании; «Новодеревенька»
→ карточка с губернией и уездом из дела, Enter по полям до Familio сохраняет;
мать после отца — окна нет (НП уже известен); Esc — назад в поле, повторный
уход не открывает. e2e шаг 9 — то же на Windows.

## 3. Ширина при растянутом окне

`.app { max-width: 40em }` → `64em`; строки формы — `flex`, поля с
`flex: 1 1` растягиваются, узкие (год, стр., счёт, дни, месяцы) держат
свою ширину. Высота при 85% и 1280 px не растёт (проверка `row.mjs` в
четырёх сочетаниях + новое 1920 px). Список «Набрано» на всю ширину.

## 4. Отец в списке «Набрано»

`entry_list` отдаёт `father` (ИОФ отца подзапросом из `person_mention`),
строка: «12.03 · Мария · отец Иван Петров Сидоров · № ж. 5 · стр. 12». Так
правка отца видна в списке — замечание Романа 23.09.

## 5. Свернуть пустой причт

`ClergyBlock`: кнопка «Свернуть» и у пустого причта; свёрнутая пустая
строка — «Церковнослужители · не указаны · Развернуть». Состояние держится между
записями в сессии (сегодня заполненный сворачивается после сохранения —
это остаётся). После перезапуска — как сейчас: заполненный свёрнут,
пустой развёрнут.
