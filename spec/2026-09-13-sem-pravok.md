# Решение: семь правок по отчёту от 13 сентября

Из замысла: `intent/2026-09-13-otchyot-romana-13-09.md`. 13 сентября 2026.

Порядок — по решению Mike: инцидент первым, дальше по влиянию на время.

## 1. Счёт по полу ребёнка — инцидент

Заменяет первую половину `spec/2026-08-28-schyot-po-polu-i-pricht.md`.

При сохранении счёт уходит в `no_male`, если пол ребёнка «М», в `no_female`,
если «Ж». Пол — из разбора имени (`parse_iof`), а не из чего-либо ещё.

Если пол неизвестен, форма **не сохраняет и говорит почему**: рядом с полем
ребёнка появляется выбор «мальчик / девочка», и до выбора кнопка сохранения
не работает. Молча положить в мужскую колонку нельзя — это и была поломка.

Критерии: (а) девочка → `no_female` заполнен, `no_male` пуст; (б) мальчик —
наоборот; (в) без пола — записи нет, а есть сообщение; (г) старые записи
не трогаются. Раскладка вынесена в `src/count.ts` и проверяется
`scripts/test_count.mjs` (в конвейере); инцидент уходит из `ОТКРЫТЫЕ`
в `scripts/test_incidents.py` с проверкой.

## 2. Перенос архива

Файл Романа в репозиторий не попадает никогда. В репозиторий попадает
**инструмент**: `db/tools/build_archive.py` читает его `.xlsm` и собирает
`архив.sqlite` — маленькую базу с той же схемой, что у программы, заполненную
только памятью подсказок: `person_index`, `spouse_index`, `place`, `usage_stat`,
`clergy_index`. Mike запускает его у себя и отправляет файл Роману.

В программе на экране «Дело» появляется кнопка «Загрузить архив из файла».
Она открывает диалог выбора файла, программа подключает архив и сливает его
в свою базу через `db/import_archive.sql` — по правилам поставки: только
дополняем, набранное не трогаем, счётчики использования складываем.

Допущение, что перенос — главный рычаг, ничем пока не подтверждено; это
единственный неподтверждённый пункт, и проверит его только замер.

Критерии: (а) после загрузки в `person_index` есть персоны из Excel;
(б) повторная загрузка того же архива не задваивает; (в) набранное до загрузки
цело; (г) слияние идёт через SQL-файл, который читает тест.

## 3. Enter на подсказке — выбрать и перейти

В полях НП, звания, вероисповедания выбор строки списком переводит фокус
на следующее поле сразу. В поле ИОФ то же — для выбора целой персоны. Для
пословной подсказки (имя, отчество) — нет: после неё продолжается набор.

Критерий: на стенде путь по Enter от «Счёт» до конца становится короче на число
полей с подсказкой. Роман: «после выбора НП перескакивает на следующее поле».

## 4. Имена и персоны по полу

`suggest_first_name` получает пол и фильтрует по `name_form.gender`.
`person_suggest` — тоже, по `person_index.gender`. Пол приходит из роли (отец М,
мать Ж) или из разбора имени (восприемники); если неизвестен — обе формы.

Критерий: в `db/test_suggest.py` матери на «Ан» не предлагается «Ананий».

## 5. Ctrl+Enter — сохранить

Из любого поля формы рождений. Обычный Enter по-прежнему ведёт по форме.

## 6. Кнопка выбора причта — всегда

Кнопка «Выбрать из списка» видна всегда. Список пуст — вместо списка строка
«пока никого: наберите руками, запомнится». В свёрнутом виде у каждого из трёх
причта своя кнопка — сменить, не разворачивая.

**Поправка к прежней спецификации.** 28 августа я записал «развернуть причт
обратно», опираясь на 82% смен на трёх сканах. Роман: сворачивание удобно.
Оба верны, если менять можно из свёрнутой строки. Сворачивание остаётся.

## 7. Высота: не больше 900 пикселей на 85%

Мерить стендом, `node стенд.mjs --scale=0.85`. Сжимать отступы, рамки, подписи,
строку разбора под ИОФ — не поля и не порядок. Цель числом: 1415 → ≤ 900.

Критерий заказчика: видит запись целиком на 85% без прокрутки.

Итог 13.09.2026 (уточнение после замера): 858 px при свёрнутом причте —
так форма выглядит на второй и всех следующих записях. На самой первой
записи, пока причт пуст и развёрнут, — 1114 px: три строки причта
с местом и званием в 900 не влезают ни при каком сжатии отступов. Это
одна запись за сессию, принято как есть; если Роман скажет, что мешает,
следующий шаг — сворачивать причт вручную ещё до заполнения.

## Чего сознательно не делаем

Не исправляем номера в уже набранных записях — обсудить с Романом отдельно.
Не переносим браки и смерти — их форм в программе ещё нет.
