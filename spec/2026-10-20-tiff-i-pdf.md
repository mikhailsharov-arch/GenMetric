## Что делаем

### 1. TIFF

- `.tif`, `.tiff` входят в список сканов. Окно браузера TIFF не показывает,
  поэтому Rust читает файл (крейт `tiff` / `image`) и отдаёт окну PNG,
  сохранённый в кэше программы (папка данных, `кэш сканов/`), — один раз на
  файл, пока файл не изменился (размер и время).
- Многостраничных TIFF не бывает (ответ 6.3): показывается первая
  страница.

### 2. PDF

- Каждая страница PDF — **отдельный лист** в общем списке: «Ф627…pdf ·
  стр. 12».
- **PDF и картинки в одной папке** (ответ 6.2): Роман сам распаковывает PDF
  в JPG «прямо в ту же самую папку, рядом с исходным PDF» — в папке
  «полные дубликаты всех страниц». Правило: **если в папке есть картинки
  (JPG, PNG, TIFF), PDF в список не входят**; если картинок нет —
  показываются листы PDF. В полосе блока скана — переключатель
  «картинки / PDF», он появляется, только когда в папке есть и то и другое;
  выбор — настройка прихода по году дела (`scan_kind_<год>`), рядом с
  папкой. Запись, привязанная к листу PDF, при выборе «картинки» свой скан
  показывает всё равно (ссылка «скан» открывает её лист).
- Картинку страницы рисовать не нужно: Rust достаёт из PDF готовый JPEG
  страницы (у его файла — один на страницу) и отдаёт окну как есть, без
  перекодирования. Страница без картинки (текст, вектор) или с несколькими
  картинками — лист с пометкой «эту страницу программа показать не
  может». Роман 20.10: у всех его PDF «каждая страница документа — это одна
  цельная фотография» — пометка остаётся только защитой.
- Запись помнит лист PDF как «имя.pdf#12» в том же поле `scan_file`; схема
  базы не меняется.
- «N из M» и переход по номеру считают листы PDF наравне с файлами;
  страница «+1» при листании — как сейчас.

### 3. Выгрузка

В колонке скана выгрузки Excel — «имя.pdf, стр. 12» (ответ 6.4:
«подходит»).

## Чего не делаем

- Отрисовки PDF с текстом и вектором (нужен движок PDF — отдельная большая
  задача, если такие файлы встретятся).
- Правки и поворота исходных файлов.

## Критерии

- Его TIFF и PDF показываются; запись, сохранённая на 12-й странице PDF,
  открывается на ней же.
- Папка с PDF и его распакованными JPG — в списке только JPG, ни одного
  двойного листа; переключатель «PDF» — только листы PDF; выбор переживает
  перезапуск.
- PDF на 55 МБ: первая страница — за секунду-две, листание без
  перечитывания файла целиком (индекс страниц в памяти).
- Тест крейта на разбор PDF (синтетический файл с JPEG-страницами) и TIFF
  1 бит; e2e Windows — показ листа PDF; стенд — список с листами PDF.

## Порядок и объём

Около двух дней: TIFF и кэш (полдня), разбор PDF и листы в списке (день),
переключатель «картинки / PDF», выгрузка, тесты, e2e (полдня). Риск PDF
другого устройства Роман снял (ответ 6.1).

## Спринт 2 (03.11.2026): как сделано

### Решения

- **Отдельный протокол окна `scan`** (`register_asynchronous_uri_scheme_protocol`
  в `main.rs`). JPG и PNG по-прежнему идут протоколом `asset`, как и с
  10.10; лист PDF и TIFF — протоколом `scan`: адрес — полный путь листа
  (`convertFileSrc(путь, "scan")`), Rust отдаёт байты сам. Готовить файлы
  заранее нельзя: просмотрщик получает адреса всех листов сразу, а
  перекодировать папку TIFF или выписать все 43 страницы PDF при открытии
  дела — долго. Так лист готовится, только когда его открыли.
- **Протокол видит только открытые папки**: Rust помнит папки, которые
  разрешил окну (`scan_open_dir`), и отдаёт только их файлы, без вложенных
  — то же правило, что у `asset`. Ответ — с `Access-Control-Allow-Origin`:
  без него просмотрщик в режиме WebGL картинку не берёт (как с `asset`).
- **PDF разбирает свой код** (`core/src/pdf.rs`), без библиотеки PDF:
  таблица ссылок (обычная и потоком, сжатые объекты — `flate2`, он и так
  был в сборке), дерево страниц, у страницы — картинки из `/XObject`.
  Ровно одна картинка JPEG (`/DCTDecode`) — лист показывается: Rust читает
  из файла только её байты (место и длина — в индексе страниц, индекс — в
  памяти, пока файл не изменился). Иначе — лист с пометкой «эту страницу
  программа показать не может». Таблица ссылок битая — индекс собирается
  проходом по файлу («N 0 obj»).
- **TIFF → PNG в кэше** (`core/src/tiff_png.rs`, крейт `tiff`): папка
  данных, `кэш сканов/`; имя — отпечаток пути, размера и времени файла.
  Чёрно-белый TIFF (1 бит) пишется PNG в 1 бит — файл мал и пишется
  быстро. Кэш не больше 500 МБ: лишнее уходит с самых старых.
- **Лист PDF в списке** — «имя.pdf#12» (тот же `scan_file`), на экране —
  «имя.pdf · стр. 12» (`sheetLabel` в `src/page.ts`).
- **Картинки и PDF в одной папке**: `ScanState.kind` — «images» или «pdf»,
  только когда в папке есть и то и другое (иначе переключателя нет);
  `other` — листы другого вида. Запись, привязанная к листу другого вида,
  показывается всё равно: блок на время показа переходит к другому виду и
  кнопкой «к набору» (концом правки) возвращается. Стали листать там после
  ссылки «скан» — работают уже здесь: вид запоминается.
- **Перетащили PDF** на окно — открывается его первая страница, вид —
  «PDF».

4. Выгрузка Excel: «имя.pdf, стр. 12», путь — к файлу PDF.
