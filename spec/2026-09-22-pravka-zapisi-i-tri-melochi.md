# Спецификация: правка сохранённой записи и три правки от 22.09

По замыслу `intent/2026-09-22-otchyot-romana-22-09.md`. Правка записи —
из бэклога, по предложению Claude и слову Mike: единственный пункт, который
закрывает уже существующую боль в данных (одна запись без пола у Романа,
любая ошибка — перенабор).

## 1. Правка сохранённой записи

Список «Набрано» показывает все записи дела (с прокруткой), у каждой —
«Открыть». Открыть можно только с пустой формы, иначе сообщение и ничего
не происходит: набранное дороже. Запись поднимается в форму целиком
(`entry_load`: `entry_get` + `mentions_of_entry` с названием НП); поля ИОФ
разбирают строку сами. Над формой — жёлтая полоса «Правка записи» с кнопкой
«Отменить»; кнопка сохранения — «Сохранить изменения». Сохранение — тот же
`entry_save` с `id`: `entry_update` + персоны переписываются (в Rust так было
с самого начала, в стенд-шим добавлено). После сохранения или отмены форма
возвращается туда, где стояли до правки (страница, счёт, год, месяцы).

Критерии: `db/test_entry.py` — `entry_get`, `mentions_of_entry` с НП
названием; стенд `edit.mjs` — открыть, поменять счёт и отца, сохранить, снова
открыть — отец новый, число записей то же, отмена возвращает пустую форму,
с набранным открыть нельзя; e2e шаг 7 на Windows.

## 2. Год с «Дела» убран

Поле «Год начала» снято; год — на форме рождений. Колонка `mk_case.year`
остаётся, форма при пустом состоянии берёт её (у новых дел она пуста —
год набирается на форме один раз).

## 3. «Прим.» свёрнуто

Пока примечание пустое — ссылка «+ примечание» справа; по клику строка
разворачивается с фокусом. Непустое примечание показано всегда. Порядок
полей не меняется. Минус одна строка у каждой персоны.

## 4. Современное ИОФ целиком

Под полем: «Василий Васильевич Промтов», а не «Васильевич». Показывается,
только если хоть что-то отличается от набранного.
