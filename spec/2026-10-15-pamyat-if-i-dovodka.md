# Спека: память «ИФ», подсказка по маске и доводка по ответу от 15.10

Замысел — `intent/2026-10-15-otchyot-romana-na-sborku-14-10.md`. Решение Mike
15.10.2026: «Д2.1 и Д2.2 с буквами — в предложенный спринт. Делай». Схема
базы меняется: две простые колонки (механизм обновления добавляет их сам),
записи не трогаются.

## Что делаем

### 1. «ИФ» запоминается вместе с человеком (долг п. 63)

Роман: «неприемлемо… программа [должна сверяться] с её исходным профилем в
базе и сама автоматически проставлять флажок „ИФ“… То же самое касается и
записей причта после перезапуска».

- Память персон (`person_index`) и память причта (`clergy_index`) получают
  колонку `name_surname`: 1 — человек сохранён как имя и фамилия, без
  отчества; 0 — нет. Правило то же, что у записи на правке (`nameSurnameOf`):
  имя есть, отчества нет, фамилия — одно слово. Каждое сохранение
  перезаписывает отметку последним вариантом.
- Подсказка персон (`suggest_person`, и обычная, и умершего), список причта
  (`list_clergy`) и причт последней записи (`last_clergy`, восстановление
  после перезапуска) отдают отметку. Выбор из подсказки, из списка причта и
  восстановленный причт ставят флажок сами; человек снимает его щелчком, как
  раньше.
- Память, набранная до обновления: отметка восстанавливается по
  сохранённым упоминаниям (`person_mention`) — человек с тем же ИОФ, когда-либо
  сохранённый без отчества с фамилией, получает 1; остальные — 0. Один раз:
  строки, где отметка уже есть, обновление не трогает.
- Отметка нужна только для двух слов: у остальных она ни на что не влияет
  (`nameSurnameNow`).

*Критерий:* сохранили «Анна Баженова» с «ИФ»; в следующей записи набрали «Анна
Баж», выбрали из подсказки — флажок стоит, под полем «без отчества, фамилия:
Баженова», у матери фамилия мужа не дописывается. Причт «Александр
Рождественский», сохранённый фамилией, после перезапуска и при выборе из
списка — с флажком. Старая база после обновления: человек, сохранённый
раньше без отчества, приходит из подсказки с флажком.

### 2. Звание по роли — и у поручителей (Д2.1)

Роман: «если я выбираю человека из базы на роль поручителя, программа должна
принудительно менять его звание с „крестьянский сын“ на „крестьянин“». Те же
пары, что у отца (`rankForRole(rank, "guarantor")` = правило отца). Только в
новой записи, только при выборе из подсказки. Восприемников не трогаем.

*Критерий:* в браках выбрали поручителем человека с «крестьянский сын» —
звание «крестьянин»; «вдовый крестьянин» — без изменений; в записи на правке
— без изменений.

### 3. Подсказка по маске «***» (Д2.2, з. 1)

Роман: «после ввода известной части, например *** Иванов Кулаев, программа
формировала выпадающий список из всех подходящих людей в базе (то есть всех
Ивановичей Кулаевых). На скане часто можно разобрать одну-две буквы».

- Первое слово поля — маска, если в нём есть «*» или это слово-заглушка
  («***», «нрзб», «?» — `is_no_name`). Тогда подсказка персон ищет по
  остальным словам: «*** Иванов Кулаев» — все, у кого после имени идёт
  «Иванов Кулаев…»; «*** Кулаев» — и «Кулаев…» сразу после имени, и после
  отчества.
- Буквы в маске: каждая «*» — любые буквы (сколько угодно, в том числе ни
  одной). «Ф***» — имена на «Ф»; «*ван» — оканчивающиеся на «ван»; «Ф*д*р» —
  «Фёдор». Сравнение — по нормализованному написанию (без регистра, «ё» как
  «е»), как у всех подсказок персон.
- Заранее не выбрана ни одна строка: того, кого набирают, в памяти нет, и
  привычный Enter подставил бы чужого (ревьюер). Выбор — стрелкой или мышью.
- Без хотя бы двух букв после маски список не показывается: «***» одна
  вывела бы всю память прихода.
- Выбор строки подставляет человека целиком — ИОФ, НП, звание, как обычная
  подсказка.

*Критерий:* в памяти «Иван Иванов Кулаев», «Фёдор Иванов Кулаев», «Пётр
Сидоров Кулаев»: «*** Иванов Кулаев» — первые двое; «Ф*** Иванов Кулаев» —
только Фёдор; «*** Кулаев» — все трое; «***» и «*** К» — пусто.

### 4. Шаг Alt+стрелок меньше и с разгоном (з. 2)

Роман: «нажимаешь стрелку, чтобы чуть-чуть подвинуть текст, а полстроки сразу
улетает… сделать его нелинейным (зажал стрелку — лист начинает ползти
медленно для микро-подстройки, а при долгом удержании скорость плавно
нарастает)».

- Короткое нажатие — сдвиг на 1/20 высоты (ширины) блока вместо 1/4.
- Удержание — лист ползёт: шаг каждого повтора клавиши начинается с 1/100 и
  плавно растёт до 1/20 за полторы секунды удержания. Повторы двигают лист
  без анимации, чтобы движение было ровным.
- Расчёт шага — чистая функция `panStep` в `src/page.ts` с тестом.

*Критерий:* одно нажатие сдвигает лист заметно меньше, чем раньше (в 5 раз);
при удержании первые полсекунды лист идёт медленно, к полутора секундам —
быстро; отпустили и нажали снова — опять медленно.

### 5. «Воздух» между событиями досье (з. 3)

Отступ между событиями блока «События» (по скриншоту: строка «стр. … ·
Открыть» почти касается даты следующего события) — около половины строки,
в единицах `--ui-scale`.

## Техдолг

- **п. 58** — при видимом скане Alt+← и Alt+→ отнимались у поля всегда.
  Теперь — только когда лист есть куда сдвинуть по горизонтали; если лист
  виден по ширине целиком, клавиша остаётся полю (в числовом поле — «±1», на
  Mac — переход по словам).
- **п. 61** — щелчок в поле номера скана посреди недописанного имени
  открывал сверку. Переход в поле номера скана — не уход из поля: ни сверки,
  ни обрезки пробела, ни правил «после ухода»; курсор вернётся туда же
  (Enter или Esc в поле номера). Ушли из номера щелчком в другое поле ввода —
  курсор проводится через исходное поле, и его правила срабатывают (в
  выпадающий список — нет: открытый, он закрылся бы).
- **п. 56** — e2e сохраняет запись со сканом: запись открыта на правку,
  «привязать к открытому», «Сохранить изменения» — у записи в базе имя
  файла без пути. И шаг e2e на память «ИФ» через настоящий Rust: сохранение
  записи с «ИФ», подсказка и список причта отдают отметку.

## Как сделано

Всё по пунктам выше. Схема 11 остаётся: колонки `name_surname` добавляет
обновление по смене отпечатка поставки. На копии базы Романа обновление —
0,2 с, записи и упоминания не тронуты (2610 и 11 966), «ИФ» получили 10
персон и 7 строк причта. Новый сценарий стенда — `_стенд/s58.mjs`.

## Что нашли агенты

**Проверяющий — «принято».** Мелочи: тёзки «Иван Петров» с отчеством и с
фамилией в одном пункте — одна строка подсказки, отметка — по последнему
сохранению; обновление ставит 1 по ИОФ без учёта пункта; маска, ничего не
нашедшая, молчит; «*» во втором слове маской не считается.

**Ревьюер — остановил выкладку, исправлено:**
1. По маске первая строка была выбрана заранее — Enter подставлял бы
   самого частого чужого человека. Теперь не выбрана ни одна (как у тёзок),
   стенд проверяет Enter.
2. Жена по мужу и отец умершего младенца приходили без «ИФ» — теперь с
   отметкой (`person_name_surname`, `birth_father`), тест крейта и стенд.
3. Проводка курсора из номера скана закрыла бы выпадающий список — для
   списков отключена.
4. `nameSurnameOf` не обрезал пробелы, в отличие от Rust и SQL, — выровнено.
5. Шаг e2e «Открыть» больше не роняет весь сценарий.

Оставлено в долг: тёзки в одной строке памяти (п. 65); уход из номера скана
не в поле (кнопка, вкладка) правил исходного поля не запускает — их
повторяет сохранение (п. 66).
