## 5. Три проверки базы на Windows (Бэклог, р. 3, п. 1)

`db/test_upgrade.py`, `db/test_parse.py`, `db/test_export.py` на Windows
падают при выходе из `tempfile.TemporaryDirectory`: соединение `sqlite3` с
базой во временной папке не закрыто, Windows открытый файл не удаляет. Сами
проверки проходят (95, 74, 142).

Решение: закрывать соединения до конца `with` (`db.close()`; в
`test_upgrade.py` — и безымянное `sqlite3.connect(seed)` у проверки «в самой
поставке тестовых строк больше нет»). Не `ignore_cleanup_errors`: оно
спрятало бы и настоящую утечку.

## 6. Тест приходов на Windows (Бэклог, р. 3, п. 2)

`cargo test -p genmetric-core` — 89 из 90: `parish::tests::open_create_and_share`
падает на `parish.rs:678` (`remove_file` → os error 32, «файл занят»).

**Разбор (19.11):** удаляется не файл прихода, а общий файл
(`common_path`). Его держит `back` — приход, открытый тестом тремя строками
выше: к соединению прихода общий файл подключён (`attach_common`). Держит
сам тест; в программе общий файл пропадает только при закрытой программе.
Пауза 3 с перед удалением не помогла — антивирус ни при чём. **Решение:**
`drop(back)` перед удалением общего файла; программа не меняется.

Прежний план разбора:
- Держит программа (соединение или подключённая база не закрывается) — это
  ошибка и у Романа: чинить в программе, тест остаётся как есть, плюс
  регресс-проверка в `test_incidents.py`.
- Держит тест или антивирус — чинить тест (закрыть то, что он держит), в
  программе ничего не менять.
Если разбор не сходится за разумное время — пункт остаётся в бэклоге с
тем, что выяснено, спринт идёт без него.
